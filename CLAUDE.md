# Storybook — notes for Claude

Static React PWA for reading public-domain children's stories. No backend; all user state lives in
`localStorage` on the device. Deployed to GitHub Pages at `/bedtime-stories/`. `SPEC.md` is the
original spec; this file describes what the code actually does.

**Docs must match code.** Any change that alters behaviour, scripts, structure or the data
contract updates this file, `README.md`, and the `Unreleased` section of `CHANGELOG.md` in the same
change. If you notice drift, fix it or flag it — don't ignore it.

## Stack

Vite 7 · React 18 · TypeScript (strict, `noUncheckedIndexedAccess`) · React Router 7 (`HashRouter`) ·
zod 3 · vite-plugin-pwa (Workbox `generateSW`) · Vitest + Testing Library (jsdom) · Playwright +
@axe-core/playwright · Lighthouse · ESLint 9 (flat) + Prettier.

## Commands

| Command               | What it does                                                                        |
| --------------------- | ----------------------------------------------------------------------------------- |
| `npm run dev`         | Dev server at `http://localhost:5173/bedtime-stories/`                              |
| `npm run build`       | Typecheck + production build to `dist/` (generates `sw.js`, manifest)               |
| `npm run preview`     | Serve `dist/` at `http://localhost:4173/bedtime-stories/`                           |
| `npm test`            | Vitest unit/component tests, incl. the compendium integrity test                    |
| `npm run test:e2e`    | Playwright (Pixel 7 profile) against `vite preview`; **build first**                |
| `npm run lint`        | ESLint + `prettier --check`                                                         |
| `npm run format`      | Prettier write                                                                      |
| `npm run typecheck`   | `tsc -b --noEmit`                                                                   |
| `npm run perf`        | Lighthouse (median of 3) on library + an Aesop story; fails below 90. Needs `dist/` |
| `npm run icons`       | Re-render PNG icons from `public/favicon.svg`                                       |
| `npm run image-sizes` | Regenerate `src/data/imageSizes.json` after changing compendium images              |

Full gate: `npm run typecheck && npm run lint && npm test && npm run build && npm run test:e2e && npm run perf`.

`BASE_PATH` env var overrides the base path (default `/bedtime-stories/`). E2E and perf scripts
assume the default.

## Data contract (summary)

`index.json`: `{ schemaVersion: 1, collections[], stories[] }`. Collections carry `language` and
`originalLanguage` (ISO 639-1). Each story entry has `id` (`<collectionId>--<slug>`),
`collectionId`, `order`, `title`, `wordCount`, `readingMinutes`, `excluded`, `flags`
(`mature-themes` | `racial-slur` | `antisemitic-caricature`), `hasImages`, and optional `workId`
(shared by translations of one tale, e.g. `grimm-khm-015`). `stories/<id>.json` adds `origin`,
`moral`, `blocks` (`p | verse | moral | heading | note | image`; image `src` is relative to
`compendium/`, JPEG or WebP, `alt` may be empty = decorative) and optional `firstPublished`,
`source` (per-book, Potter) and `originalTitle` (Hunt). Everything is validated with zod on load;
failures throw `DataError` (`kind: network | http | invalid`). 614 stories, 12 collections, ~5 MB
of story JSON and ~31 MB of illustrations. Tests derive counts from `index.json`; never hardcode
them.

`tags.json`: `{ schemaVersion: 1, cultures: {id,label}[], themes: {id,label}[], stories: { [id]:
{ cultures, themes } } }`. Every story has ≥1 of each; every defined tag is used (integrity test).
12 cultures (tale origin, not editor: Lang's book is split by `origin`) and 17 themes. Regenerate
with `python3 tools/tag_stories.py` after any data change.

## Behaviour rules

- **Visibility** (`domain/visibility.ts`): `excluded` hidden unless `showExcluded`; `mature-themes`
  hidden unless `showMature`. Applied in library, search, collections, favorites, continue-reading,
  prev/next and the picker. A hidden story opened by URL shows a "hidden" message, not the text.
- **Store** (`storage/store.ts`): key `storybook:v1` holds `{ version, settings, favorites,
progress, history, recentPicks, openStoryId }`. Progress entries also carry `blockCount` (when
  known) so the shelf can show a percentage. Each field falls back to its default independently; corrupt
  JSON resets with a `console.warn`. `migrate()` is the version seam (v1 = identity). Ids not in
  the index are pruned when the index loads. History caps at 200, recent picks at 10. Cross-tab
  changes are picked up via the `storage` event.
- **Resume**: `useReadingTracker` (IntersectionObserver) reports the topmost visible block,
  throttled to 800 ms; only indices > 0 are saved. Reopening offers "Continue from where you left
  off" — never auto-jumps. Seeing the final block marks the story read and clears its progress.
  Granularity is per block; some Grimm paragraphs are a screen or more long.
- **Reading tab** (`pages/ReadingPage.tsx`, middle of the tab bar): the reader marks a visible
  story as the open story when it mounts; finishing it (final block seen) or the reader's
  **Close book** button clears it. Tapping Reading with an open story redirects to
  `#/s/:id?resume=1`, which scrolls straight to the saved block with no "Continue?" prompt, and the
  tab shows as current while you read that story. With nothing open it shows the shelf: the most
  recent in-progress story (percent and minutes left), the others, and the last 5 finished.
- **Typography** (`domain/typeset.ts`): several sources are ASCII (`"`, `'`, `--`). The data
  client typesets titles, block text, morals, origins and alt text into curly quotes and em
  dashes on load; the files on disk are never rewritten.
- **Other versions**: the reader lists visible stories sharing the current story's `workId`, and
  the picker treats every translation of a recently picked tale as recent. Potter stories show
  their own year and a Source link in the byline.
- **Length** (`domain/length.ts`, `components/LengthSlider.tsx`): a two-handled slider over the
  stops 1, 2, 3, 5, 7, 10, 15, 20, 30, 45, 60+ min (dense at the short end, where most stories
  are). `max: null` means no upper bound. Used by the library filter (default: any length) and
  Surprise me (persisted as `picker.minMinutes`/`maxMinutes`, default up to 5 min). When both
  handles meet in the upper half, Shortest is raised above Longest so they can be pulled apart.
- **Tags**: themes come from vocabulary density over each story's text and title, collection
  rules (Aesop → fables, Kipling → how-things-began, Potter → animals) and hand `OVERRIDES` in the
  script. `gentle` = no monsters/ghosts, not mature, and few violent words. It's an editorial first
  pass: fix a wrong tag by adding to `OVERRIDES`, never by editing `tags.json`. The library has a
  "Browse by Collections / Cultures / Themes" switch (`?by=`), tag pages at `#/tags/:kind/:id`,
  tag chips in the reader, and search matches tag labels. Counts respect visibility.
- **Surprise me** (`domain/picker.ts`, `domain/presets.ts`, `pages/SurprisePage.tsx`):
  `pickMany` returns up to 1 or 3 distinct stories (never two translations of one tale), avoiding
  the last 10 picks and their translations unless that leaves too few. Filters: collections,
  length, unread/favorites, and culture/theme tri-state chips (tap: include → exclude → any;
  include = any of, exclude = none of, exclude wins). Presets (Quick & gentle, Something new =
  unread from cultures not yet read, Old favorite) replace all filters but keep the count. All of
  it persists in `settings.picker`. Cards flip in, except under reduced motion. "Recently picked"
  lists the last 10. If fewer stories match than asked for, the page says so.
- **Collection labels** (`domain/collectionLabel.ts`): where two collections share a title (the
  two "Japanese Fairy Tales"), the credited person's surname is appended wherever a collection is
  named next to a story or as a filter.
- **Swipe actions** (`components/useSwipeReveal.ts`, `StoryRow`): swipe a story row left to
  reveal "Mark unread" (read stories) or "Mark read". One row open at a time; a tap on an open row
  closes it; the click ending a swipe never navigates. The action button is always in the tab
  order and accessibility tree, and focusing it opens the row, so no gesture is required.
  `store.markUnread` removes the story from history only; saved progress is kept.
- **Layout stability**: images render with `width`/`height` from `imageSizes.json` so space is
  reserved before they load; a story's first block, if an image, loads eagerly with
  `fetchpriority="high"`. Prev/next is rendered only once the story has loaded. These keep CLS
  near zero; without them Lighthouse performance on illustrated fables swung between 78 and 98.
  The integrity test fails if `imageSizes.json` doesn't match the images on disk.
- **Theme**: `system` (default) = sepia when the OS is light, dark when the OS is dark, tracked
  live. Applied app-wide via `html[data-theme]`; an inline script in `index.html` sets it before
  first paint; `meta[name=theme-color]` follows.
- **Offline**: app shell, `index.json` and `tags.json` precached; story JSON stale-while-revalidate (`stories`
  cache), images cache-first (`images` cache); both capped at 1000 entries. The settings download
  (optionally text-only) writes straight into those caches; its advertised sizes live in
  `OFFLINE_MB` and the integrity test fails if they drift >25% from disk. Cache names in `vite.config.ts` and `offline/download.ts` must
  match.

## Data and licensing notes

- Don't use Potter characters (Peter Rabbit etc.) in the app's name, icon or marketing: Frederick
  Warne holds trademarks on them. Showing the texts is fine.
- Content flags and exclusions in the patches are editorial first passes (see each patch's notes);
  `excluded` alone decides the antisemitic-caricature stories.

## Deviations from SPEC.md

- `HashRouter`, so URLs are `#/s/:storyId` etc. GitHub Pages has no SPA fallback; hash routing
  avoids a 404.html hack and works offline under the service worker.
- Sessions were implemented in one pass, so the interim Session 2/3 settings wrapper never existed;
  settings went straight into `storage/store.ts`.
- Theme has a fourth option, `system` (default), per the request to follow the phone's dark/light
  setting. Explicit light/sepia/dark still override it.

## Testing conventions

- Tests first for new behaviour. Pure logic lives in `src/domain` and gets table tests.
- Component tests render through `src/test/renderApp.tsx` (real routes, mocked `fetch`, fresh
  store). Use roles/labels, not class names, where possible.
- Randomness is injected; use `mulberry32` from `src/test/fixtures.ts`.
- jsdom has no IntersectionObserver — use `installFakeIO()`.
- `src/data/integrity.test.ts` runs in Node over the real `public/compendium/`; keep it green when
  regenerating data.
- E2E offline tests start their own preview server and kill it to go offline: Chromium's offline
  emulation does not reach service-worker fetches.
