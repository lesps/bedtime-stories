# Storybook — notes for Claude

Static React PWA for reading public-domain children's stories. No backend; all user state lives in
`localStorage` on the device. Deployed to GitHub Pages at `/bedtime-stories/`. `SPEC.md` is the
original spec; this file describes what the code actually does.

**Docs must match code.** Any change that alters behaviour, scripts, structure or the data
contract updates this file, `README.md`, and the `Unreleased` section of `CHANGELOG.md` in the same
change. If you notice drift, fix it or flag it — don't ignore it.

## Stack

Vite 7 · React 18 · TypeScript (strict, `noUncheckedIndexedAccess`) · React Router 7 (`HashRouter`) ·
zod 3 · vite-plugin-pwa (Workbox `generateSW`) · Vitest + Testing Library (jsdom) · Playwright +
@axe-core/playwright · Lighthouse · ESLint 9 (flat) + Prettier.

## Commands

| Command             | What it does                                                                    |
| ------------------- | ------------------------------------------------------------------------------- |
| `npm run dev`       | Dev server at `http://localhost:5173/bedtime-stories/`                          |
| `npm run build`     | Typecheck + production build to `dist/` (generates `sw.js`, manifest)           |
| `npm run preview`   | Serve `dist/` at `http://localhost:4173/bedtime-stories/`                       |
| `npm test`          | Vitest unit/component tests, incl. the compendium integrity test                |
| `npm run test:e2e`  | Playwright (Pixel 7 profile) against `vite preview`; **build first**            |
| `npm run lint`      | ESLint + `prettier --check`                                                     |
| `npm run format`    | Prettier write                                                                  |
| `npm run typecheck` | `tsc -b --noEmit`                                                               |
| `npm run perf`      | Lighthouse on library + an Aesop story; fails below 90 perf/a11y. Needs `dist/` |
| `npm run icons`     | Re-render PNG icons from `public/favicon.svg`                                   |

Full gate: `npm run typecheck && npm run lint && npm test && npm run build && npm run test:e2e && npm run perf`.

`BASE_PATH` env var overrides the base path (default `/bedtime-stories/`). E2E and perf scripts
assume the default.

## Layout

```

public/*.png, favicon.svg PWA icons (generated by tools/make-icons.mjs)

tools/lighthouse.mjs      scripted Lighthouse check

                          IndexProvider.tsx (loads index, prunes unknown ids from the store)

                          search normalisation, excerpt
src/storage/              store.ts (single versioned localStorage key), StoreProvider.tsx (hooks)
src/reader/               ReaderPage, BlockRenderer, ReaderControls, ProgressBar, useReadingTracker
src/pages/                Library, Collection, Favorites, Surprise, Settings, About, NotFound
src/offline/download.ts   "Make all stories available offline" (writes into the SW's caches)
src/app/                  App/routes/layout, theme (system/light/sepia/dark), online status hook
src/test/                 setup, fixtures (incl. mulberry32), renderApp harness, fake IntersectionObserver

```

## Data contract (summary)

`index.json`: `{ schemaVersion: 1, collections[], stories[] }`; each story entry has `id`
(`<collectionId>--<slug>`), `collectionId`, `order`, `title`, `wordCount`, `readingMinutes`,
`excluded`, `flags` (`mature-themes` | `racial-slur`), `hasImages`. `stories/<id>.json` adds
`origin`, `moral`, `blocks` (`p | verse | moral | heading | note | image`; image `src` is relative
to `compendium/`). Everything is validated with zod on load; failures throw `DataError`
(`kind: network | http | invalid`). 319 stories, 6 collections.

## Behaviour rules

- **Visibility** (`domain/visibility.ts`): `excluded` hidden unless `showExcluded`; `mature-themes`
  hidden unless `showMature`. Applied in library, search, collections, favorites, continue-reading,
  prev/next and the picker. A hidden story opened by URL shows a "hidden" message, not the text.
- **Store** (`storage/store.ts`): key `storybook:v1` holds `{ version, settings, favorites,
progress, history, recentPicks }`. Each field falls back to its default independently; corrupt
  JSON resets with a `console.warn`. `migrate()` is the version seam (v1 = identity). Ids not in
  the index are pruned when the index loads. History caps at 200, recent picks at 10. Cross-tab
  changes are picked up via the `storage` event.
- **Resume**: `useReadingTracker` (IntersectionObserver) reports the topmost visible block,
  throttled to 800 ms; only indices > 0 are saved. Reopening offers "Continue from where you left
  off" — never auto-jumps. Seeing the final block marks the story read and clears its progress.
  Granularity is per block; some Grimm paragraphs are a screen or more long.
- **Theme**: `system` (default) = sepia when the OS is light, dark when the OS is dark, tracked
  live. Applied app-wide via `html[data-theme]`; an inline script in `index.html` sets it before
  first paint; `meta[name=theme-color]` follows.
- **Offline**: app shell + `index.json` precached; story JSON stale-while-revalidate (`stories`
  cache), images cache-first (`images` cache, 150 max). The settings download button writes
  straight into those caches, so cache names in `vite.config.ts` and `offline/download.ts` must
  match.

## Deviations from SPEC.md

- `HashRouter`, so URLs are `#/s/:storyId` etc. GitHub Pages has no SPA fallback; hash routing
  avoids a 404.html hack and works offline under the service worker.
- Sessions were implemented in one pass, so the interim Session 2/3 settings wrapper never existed;
  settings went straight into `storage/store.ts`.
- Theme has a fourth option, `system` (default), per the request to follow the phone's dark/light
  setting. Explicit light/sepia/dark still override it.

## Testing conventions

- Tests first for new behaviour. Pure logic lives in `src/domain` and gets table tests.
- Component tests render through `src/test/renderApp.tsx` (real routes, mocked `fetch`, fresh
  store). Use roles/labels, not class names, where possible.
- Randomness is injected; use `mulberry32` from `src/test/fixtures.ts`.
- jsdom has no IntersectionObserver — use `installFakeIO()`.
- `src/data/integrity.test.ts` runs in Node over the real `public/compendium/`; keep it green when
  regenerating data.
- E2E offline tests start their own preview server and kill it to go offline: Chromium's offline
  emulation does not reach service-worker fetches.
